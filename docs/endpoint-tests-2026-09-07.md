# Endpoint verification — Guesty CLI 1.2.0

The audit changed 74 named commands (14 additions and 60 adjustments), covering 68 distinct method/path pairs. Every pair has passing offline request-contract tests. The complete local suite passed **463 tests**, with no failures or skips, and the generated CLI contract matches source and the current OpenAPI reference.

Live reads succeeded for **41** of these endpoint routes. 2 returned upstream/account errors, 5 were verified offline without retrieving production secrets or inventing fixtures, and all 20 mutation routes were tested offline. Empty successful responses prove request acceptance, not behavior on an unavailable record. No messages, payments, reservation changes, calendar changes, uploads, token creation, or token-cache writes were performed against production.

Offline cases assert HTTP method, path, query names/values/serialization, and JSON body or absent body. Multipart cases inspect file bytes, name, MIME type, and form fields. Failure tests cover missing/invalid arguments before any request. Shared transport tests additionally cover authentication, scope validation, query merging, headers, body types, timeouts, retries, redirects, response decoding, rate limits, and pagination.

## Interpretation of live findings

- Legacy reservation confirmation and listing filters were checked with both a selected listing and a deliberately nonexistent confirmation code. V3 search returned the selected listing and zero matches for the nonexistent code; an initial upstream 500 later recovered.
- Single-listing review averages initially failed with HTTP 400 because Guesty parsed one repeated-key value as a scalar. The corrected `listingIds[]` request returned HTTP 200; tests cover one and multiple listing IDs.
- Both journal endpoints rejected omission of `transactionDate` with HTTP 400, despite the August 26 changelog. The required date filter and existing 30-day default remain.
- Reservation logs repeatedly returned HTTP 503 with `name resolution failed`; the expense endpoint returned HTTP 403 for the available account. Successful live use of these two capabilities remains unverified.
- Conversation list/get/posts, disbursement list/get, selected folio fields, payment reports, owner statements, and guest payment methods with reservation context returned successful responses. Customer records and tokens are excluded from this evidence.
- The generic `raw` command has an unbounded route surface; its request behavior is covered in [client tests](../test/client.test.mjs). The 68-route matrix counts named endpoints, not arbitrary user-supplied paths.
