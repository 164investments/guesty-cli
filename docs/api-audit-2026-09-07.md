# Guesty CLI 1.2.0 API audit

The audit reviewed the complete tracked runtime and maintenance scripts, refreshed the current Guesty reference, and corrected 74 named commands: 14 additions and 60 adjustments across 68 endpoint routes. The local release candidate passes 463 tests with no failures or skips. The [endpoint matrix](endpoint-tests-2026-09-07.md) records an exact-request test for every added or adjusted route and the limits of live verification.

## Scope and sources

The review used both official documentation indexes, the current endpoint schemas, guides, and changelogs. All 450 unique Markdown pages linked by the Open API and Booking Engine indexes were retrieved successfully; the historical Open API changelog added 45 earlier pages. The resulting 495-page public corpus contains 336 Open API reference pages, 59 guides, 55 changelog entries and one recipe, plus 21 Booking Engine reference pages, 11 guides, ten changelog entries and two recipes. Reference overview pages are not counted as HTTP operations.

The current OpenAPI document contains 333 operations across 237 paths. The old catalog had 308 real HTTP operations and a bogus `X-SUMMARY` operation; the refresh adds 26 operations, removes the metadata entry, and follows the current documented operation set. `openapi-spec.json` preserves complete schemas and shared components. `api-spec.json` is the indexed catalog, and `guesty-cli-spec.json` maps 337 CLI actions to current request/response definitions. Named commands cover 322 documented operations across 321 unique routes; one documentation entry is a fixed-query variant of the listing endpoint.

## Documentation updates and deliberate deferrals

Guesty announced retirement of legacy reservation APIs at the end of 2026. This release adds current v3 search and preserves explicit legacy commands where callers depend on their response format. Some legacy payment replacements remain pending in Guesty's documentation. Deprecated integration, custom-field and owner-reservation routes remain available with deprecation metadata instead of silently changing their contract. [Retirement notice](https://open-api-docs.guesty.com/changelog/2026-07-30)

The review included v3 search/logs/travel information, comments/booking date, virtual-card reservation context, adjustable line items, disbursements, and the webhook documentation refresh. The journal changelog says dates became optional, but live requests to both journal endpoints without `transactionDate` returned HTTP 400; the existing required filter remains. [May 12 update](https://open-api-docs.guesty.com/changelog/2026-05-12), [May 26 update](https://open-api-docs.guesty.com/changelog/2026-05-26), [June 23 update](https://open-api-docs.guesty.com/changelog/2026-06-23), [August 20 update](https://open-api-docs.guesty.com/changelog/2026-08-20), [August 26 update](https://open-api-docs.guesty.com/changelog/2026-08-26), [September 2 update](https://open-api-docs.guesty.com/changelog/2026-09-02)

Eleven documented operations have no dedicated command in this release. They remain available through `raw` and the complete packaged schemas: partial business-model update; four channel-commission-v2 account/listing operations; four owner-payout-method operations; and vendor create/patch. New wrappers for these financial configuration surfaces can be added with account-specific use cases and fixtures. The generated contract lists every remaining route under `referenceCoverage.missingImplementedEndpoints`.

The Booking Engine review covered revised inquiry/quote paths, taxes and upsells, booking-flow deprecations, and pilot pricing/cursor changes. It remains a separate API scope. Normal CLI commands and `raw` use only Open API authentication; `guesty token --beapi` provides a separately validated cached token for an explicitly scoped external workflow. No speculative Booking Engine commands or token creation were added.

## Verification evidence

- `npm ci` installed the locked dependencies successfully; strict TypeScript compilation passes.
- `npm run check` passes all **463 tests** and the generated-contract consistency check. This includes the original 66 authentication cases plus transport, input/output, update, endpoint, calendar/reservation and reference regressions.
- Independent coverage review found **68 of 68** changed endpoint routes covered, with zero missing exact-request tests.
- Live reads passed on **41** changed endpoint routes. Five read routes were tested offline because no suitable scoped fixture was available or secret retrieval was unnecessary. Reservation logs returned upstream 503 and expenses returned account-specific 403. All 20 changed mutation routes were tested offline; no production business records were changed. See the [full matrix](endpoint-tests-2026-09-07.md).
- Live negative/positive checks confirmed corrected legacy and v3 reservation filtering. Live review averages exposed the single-value array parsing issue; `listingIds[]` fixed it and passed both offline single/multiple cases and the live single-listing check.
- `npm run refresh:api-spec` successfully retrieves all 333 current operations. Schema extraction and isolated knowledge generation both process 333 operations. `git diff --check` is clean.
- `npm pack` produced a 1.5 MB compiled tarball containing 104 intended files, with no environment files, tokens, caches or development dependencies. A clean temporary-prefix installation reports 1.2.0 and exposes the new command help.
- Release automation requires a fresh check and clean package install before uploading the tarball. The public [Check runs](https://github.com/164investments/guesty-cli/actions/workflows/check.yml), [Release runs](https://github.com/164investments/guesty-cli/actions/workflows/release.yml), and [v1.2.0 release](https://github.com/164investments/guesty-cli/releases/tag/v1.2.0) are the durable deployment evidence.

Live reads used existing cached tokens and scoped records, with no raw customer records or tokens copied into this repository. No schema changes or migrations were required.

## Published artifact and legacy upgrades

Version 1.2.0 was published from production commit `21151fb`. Its Node 18/22 checks and [release workflow](https://github.com/164investments/guesty-cli/actions/runs/34164557457) passed. The downloaded checksum verified, all 104 packaged files matched the frozen source/build, and the activated installation passed legacy/v3 reservation-filter, single-listing review-average and calendar reads.

Additional testing of the actual npm 1.1.0 CLI's `guesty update` found an npm 11.17 global Git-install bug. npm passes its global setting into Git dependency preparation, so the nested installer targets the same global directory as the outer installer. This can leave build dependencies missing or cause a directory-renaming collision. Direct reproductions using fresh prefixes/caches and clean npm configuration confirmed both failures. Repairing compiler preparation inside the package cannot reliably resolve a collision that occurs before its scripts run; that workaround is excluded from the release.

Version 1.2.1 retains the verified 1.2.0 API implementation and clarifies the reliable migration: install its compiled GitHub tarball for older versions, then use `guesty update` on 1.2.0 and later. The new updater already installs release tarballs and avoids the Git build path. The follow-up changes package/version metadata and upgrade documentation only; the 463-test API/runtime suite and endpoint matrix remain applicable. No endpoints or database schemas changed.
